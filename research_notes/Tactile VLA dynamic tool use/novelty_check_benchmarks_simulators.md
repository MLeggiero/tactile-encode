# Novelty check: tactile slow-fast VLA for high-energy tool use (hammer / power-drill) — nearest-neighbor map, benchmarks, simulators, stacks

Scope date: 28 September 2026. Method: direct key-phrase web searches (~60 queries), abstract/full-text verification of every candidate via arXiv/ar5iv/project pages, GitHub repository search, and documentation pages for benchmarks/simulators. The six criteria used throughout:

- **C1** VLA and/or learned world model as the *slow* high-level policy
- **C2** paired with a *high-frequency* low-level controller (learned or classical, tactile/force-driven)
- **C3** inputs = tactile + vision + joint state + joint effort/torque
- **C4** dynamically regulates grip force, grip position/regrasp, and applied torque
- **C5** high-energy / high-frequency tool-mediated task (hammer a nail; power-drill a screw, incl. bit-engagement detection)
- **C6** goal object is two degrees of separation away (robot -> tool -> target)

Scoring key: **Y** = clearly meets, **P** = partially meets, **N** = does not meet / no evidence.

## Key question 1 — Does a project doing "exactly this" exist? Nearest-neighbor map and verdict

### Takeaway
No paper, product, or repository found as of September 2026 combines all six criteria; the field has split into (a) VLA/world-model systems that *do* hammer or power-screw but are RGB-only with no fast tactile loop (Being-H0.7, π's RL Token, iTUP), (b) slow-fast tactile/force VLAs that have the architecture but are only evaluated on insertion/wiping/peeling-class tasks (FAVLA, TacMamba, AT-VLA, UniTacVLA, RDP, TouchWorld, TacPAC), and (c) tactile screwdriving/grip-force works that lack a VLA and use manual tools (DexScrew, HTT, Tactile-VLA, UMI-FT, FARM). Nothing found detects drill-bit engagement inside a learned policy; that capability exists only as classical force/torque anomaly detection.

Row-level evidence:

- Being-H0.7 lists 12 real-world tasks, Task 12 prompt "Pick up the hammer and drive the nail into the hole"; "Across all experiments, the policy relies on RGB-only visual observations"; control rates 20 Hz (Adam-U), 10 Hz (G1), 20 Hz (FR3); only suite-level scores reported — [Being-H0.7 full text](https://arxiv.org/html/2605.00078v1); abstract describes it as "a latent world-action model" combining "future-aware reasoning with visual-language-action policies" — [arXiv 2605.00078](https://arxiv.org/abs/2605.00078)
- RL Token (all authors Physical Intelligence): "The robot must use an electric screwdriver to drive an M3 screw into a threaded receptacle"; inputs are up to four RGB camera images plus joint position, base VLA π0.6, 50 Hz, ~5 h of real RL data, critical-phase success "from 20% to 65%" and "up to 3× speedup"; no force/torque or tactile input — [RL Token full text](https://arxiv.org/html/2604.23073); four tasks "screw installation, zip tie fastening, charger insertion, and Ethernet insertion" — [arXiv 2604.23073](https://arxiv.org/abs/2604.23073). (The π blog post at https://www.pi.website/research/rlt returned HTTP 429 on every attempt; details taken from the arXiv version.)
- iTUP: GPT-4o tool/contact grounding + SDG-Net physics-informed grasp selection; tasks "hammering nails, sweeping toys, and knocking over towers"; UR5e + Robotiq; 76.67% success; "Previous attempts involving hammering tasks never consider the torque incurred during hammer-nail interaction…tool slippage or displacement due to unstable grasps" — [iTUP v1](https://arxiv.org/html/2505.01399v1); later abstract: selects grasps "by minimizing predicted interaction wrench along a task-conditioned trajectory", "+17.5% real-world success", "suppresses induced torque up to 17.6%" — [arXiv 2505.01399](https://arxiv.org/abs/2505.01399)
- SimToolReal: 22-DoF Sharpa hand on KUKA iiwa 14; policy inputs = tool 6D pose, grasp-region bounding box, proprioception, goal; "efficient in-hand object rotations"; no tactile/force; 24 task trajectories incl. hammer, evaluated as trajectory following; limitation quoted: "it does not guarantee functional task completion, especially for high-force interactions" — [SimToolReal full text](https://arxiv.org/html/2602.16863); "24 tasks", "6 tool categories", "120 real-world rollouts", "+37% over retargeting/fixed-grasp" — [arXiv 2602.16863](https://arxiv.org/abs/2602.16863)
- DexScrew: XHand (12 DoF) with 120-element 3-axis pressure arrays per fingertip (0.05 N threshold); manual screwdriver (octagonal/dodecagonal handles in sim); IsaacGym at 200 Hz with 20 Hz control; screwdriving progress 41.6% direct sim-to-real vs 95% with tactile BC + history; nut-bolt 95–97.5% — [DexScrew full text](https://arxiv.org/html/2512.02011); three-stage pipeline (RL in sim -> skill-based teleop -> BC with tactile) — [arXiv 2512.02011](https://arxiv.org/abs/2512.02011)
- Tool-as-Interface: Kinova Gen3, RGB (RealSense D415), diffusion policy maps single-view RGB to SE(3) action; "hammering a 3D-printed nail"; 13/13 vs 0/13 for teleop baseline — [full text v2](https://arxiv.org/html/2504.04612v2); vision-only 3D reconstruction with Gaussian splatting — [arXiv 2504.04612](https://arxiv.org/abs/2504.04612)
- HMAMP: hammering is "one challenging manipulation task"; real robot-arm hammering; adversarial motion priors from human motion — [arXiv 2510.24257](https://arxiv.org/abs/2510.24257)
- Tactile-VLA: tasks = USB/charger insertion, tabletop grasping, board wiping (no tools beyond an eraser); UMI gripper with dual normal+shear tactile sensors, "100Hz tactile feedback and 20Hz visual data"; "gripper width is used in parallel to control the internal grasping force"; charger insertion 90% vs 25–40% — [Tactile-VLA full text](https://arxiv.org/html/2507.09160)
- ForceVLA: "Building upon the π0 framework, it integrates vision, language, proprioception, and 6-axis force feedback"; tasks "Bottle Pumping, Plug Insertion, USB Drive Insertion, Whiteboard Wiping, and Cucumber Peeling"; 60.5% avg — [ForceVLA site](https://sites.google.com/view/forcevla2025); +23.2% over π0 baselines — [arXiv 2505.22159](https://arxiv.org/abs/2505.22159)
- FAVLA: π0-based; slow VLM predicts near-future force variation, fast action expert "runs at a variable high frequency" using latest force; 6-axis F/T at flange, tasks "USB Insertion, Gear Assembly, Box Flipping, and Board Wiping", 80.8% avg, +13.8 pts over ForceVLA — [FAVLA full text](https://arxiv.org/html/2602.23648)
- TacMamba: Mamba tactile history compressor "with O(1) inference latency (0.45 ms)", >100 Hz tactile alongside π0.5; demos are counting and implicit state switching — [arXiv 2603.01700](https://arxiv.org/abs/2603.01700)
- AT-VLA: "slow visual-language stream…and a fast tactile control stream", "real-time close-loop responses within 0.04 s" — [arXiv 2605.07308](https://arxiv.org/abs/2605.07308); code [github.com/clorislili/AT-VLA](https://github.com/clorislili/AT-VLA)
- UniTacVLA: "tactile-action mixed controller that combines real-time and predicted tactile feedback to refine low-frequency action chunks with high-frequency corrections"; tasks adjustment, insertion, wiping, assembly — [arXiv 2606.31723](https://arxiv.org/abs/2606.31723)
- RDP: slow latent diffusion policy + "fast asymmetric tokenizer for closed-loop tactile feedback control at high frequency" — [arXiv 2503.02881](https://arxiv.org/abs/2503.02881); tasks peeling/wiping/bimanual lifting with success 0.95/0.87/0.70 vs DP 0.44/0.57/0.00; fast policy "<1 ms" — [RDP site](https://reactive-diffusion-policy.github.io/); repo supports GelSight Mini, MCTac, "(optional) joint torque sensors", 24 fps recording — [RDP repo](https://github.com/xiaoxiaoxh/reactive_diffusion_policy)
- TouchWorld: slow VL planning + tactile world-model prediction; fast "tactile-conditioned refinement policy performs online residual correction"; six tasks (Water Flower, Tabletop Clearing, Cup Insertion, Power Plug Insertion, Pot Wiping, Tissue Pulling) on a humanoid with Wuji hands and a JQ tactile glove; 65.0% clean / 53.7% perturbed — [TouchWorld full text](https://arxiv.org/html/2607.07287); [arXiv 2607.07287](https://arxiv.org/abs/2607.07287)
- TacPAC: world-action model with tactile prediction + "real-time action correction" of unexecuted chunk actions, "20.7× cheaper than regenerating the chunk"; 22% -> 64% across five real tasks (insertion, fragile handling, reorientation, long-horizon) — [arXiv 2609.05266](https://arxiv.org/abs/2609.05266)
- Figure Helix 02 (27 Jan 2026): S2 reasons slowly, S1 at 200 Hz, "System 0 (S0) executes at 1 kHz, handling balance, contact, and coordination"; fingertip tactile sensors detect "as small as three grams" enabling "contact-aware, force-modulated grasping"; demos = dishwasher, bottle-cap unscrewing, pill extraction, syringe; no power tools — [figure.ai/news/helix-02](https://www.figure.ai/news/helix-02)
- HTT: Sharpa hand on Franka, five fingertip optical tactile sensors, "proprioception and finger-tip tactile sensing" only; "Toy Screw: fingers must repeatedly grip and rotate a screw until it is fully tightened"; 95% vs 50% (raw wrench) vs 5% (proprio) — [HTT full text](https://arxiv.org/html/2606.29948)
- UMI-FT: handheld gripper with "compact, six-axis force/torque sensors on each finger"; policy "predicts position targets, grasp force, and stiffness"; tasks whiteboard wiping, zucchini skewering, lightbulb insertion — [arXiv 2601.09988](https://arxiv.org/abs/2601.09988); ACP learns spatially/temporally varying compliance, ">50% improvement" — [arXiv 2410.09309](https://arxiv.org/abs/2410.09309)
- Holladay: constraint-based planning over grasps, arm and tool paths under "joint torque limits, grasp stability" for tasks like pulling a nail with a hammer claw — [IROS 2019 PDF](https://dspace.mit.edu/bitstream/handle/1721.1/137604/holladay-iros19.pdf?sequence=2&isAllowed=y); multi-stage forceful manipulation covers "drilling through a board, cutting a carrot, and twisting a nut" — [arXiv 2101.02679](https://arxiv.org/pdf/2101.02679), [IJRR 2024](https://journals.sagepub.com/doi/10.1177/02783649231198560)

### Inferences
- **Verdict: "exactly this" does not exist as of Sept 2026.** The maximum any single work scores is roughly 4 of 6: Being-H0.7 and RL Token satisfy C1+C5+C6 but are explicitly RGB-only with no tactile/force loop (C2/C3/C4 = N); FAVLA/TacMamba/AT-VLA/UniTacVLA/TouchWorld/TacPAC/Helix-02 satisfy C1+C2 (+partial C3/C4) but none evaluates a hammer or power-drill task; DexScrew/HTT do tactile screwdriving with regrip but with a manual screwdriver, no VLA, and no vision/torque.
- The three ingredients the idea uniquely fuses — (i) slow VLA/world model, (ii) kHz-class tactile/torque loop that *regulates grip force, regrasp and applied torque*, and (iii) impulsive/vibratory tool tasks with engagement detection — have each been demonstrated separately but never on the same system. Joint-torque conditioning of the fast loop is essentially absent (RDP lists joint-torque sensors only as optional; no VLA uses joint effort as an input).
- Drill-bit engagement/cam-out detection is a clear white space for learned policies: all existing detectors are offline/anomaly-style classifiers on F/T signals, not policy-internal state estimates that drive grip/torque regulation.
- RL Token is the most relevant "successful project" to watch (π0.6 + online RL genuinely drives M3 screws with an electric screwdriver) — but its own analysis shows that precision comes from RL fine-tuning of an RGB policy at 50 Hz, i.e., the differentiator of the proposed idea is tactile/torque sensing and a fast loop, not the task alone.
- The "two degrees of separation" framing (C6) is met by every hammering/screwdriving neighbor, so it is not by itself a novelty; novelty lies in sensing the tool-target interaction through the tool (tactile + joint torque) and closing a fast loop on it.

### Gaps
- Physical Intelligence's blog pages (RL Token, π*0.6) returned HTTP 429 on all attempts; details were taken from the arXiv versions instead.
- No primary source found for any Tesla Optimus, Sanctuary, 1X, Apptronik or Unitree demo of autonomous power-tool use (web-search budget exhausted before a dedicated sweep; only aggregator pages were returned).
- Being-H0.7 reports no per-task success for its hammer task, so whether the nail is actually driven is unverified.
- The "Learning Dexterous Tool Use" candidate could not be resolved to a specific paper; "MERL screw insertion" details come from a secondary news article only; the CMU screwdriving dataset paper was not fetched (ResearchGate).
- Task lists for TAO-Force, ImplicitRDP and T-Rex were not in their abstracts; a tool task cannot be ruled out for those three.

## Key question 2 — Benchmarks and simulators containing hammer / drill / screw tasks (and real-world counterparts)

### Takeaway
Hammer tasks exist only as low-fidelity sim tasks (Meta-World "hammer", Adroit/DAPG hammer, RoboTwin "Beat Block Hammer", MimicGen "Hammer Cleanup", HumanoidToolBench "IceBreak", robosuite hammer handover); the only benchmarks with real physical screwing are FurnitureBench (gripper-rotated screws, no driver) and the NIST task boards (nut/bolt threading), while no benchmark, sim or real, contains power-drill screw driving.

### Cited Findings
- **Meta-World** (MuJoCo, 50 tasks, MIT): hammer task described as "Hammer a screw on the wall. Randomize the hammer and the screw positions" — [task descriptions](https://metaworld.farama.org/benchmark/task_descriptions/); MuJoCo/MIT — [GitHub](https://github.com/Farama-Foundation/Metaworld). No real counterpart.
- **Adroit / DAPG** (MuJoCo, 24-DoF ADROIT hand): "pick up and hammer with significant force to drive the nail into the board. Nail position is randomized and has dry friction capable of absorbing up to 15N force"; "Though the simulation supports tactile feedback, we do not use it in this work" — [DAPG (ar5iv)](https://ar5iv.labs.arxiv.org/html/1709.10087); packaged in RoboHive (MuJoCo, Apache-2.0, Hand-Manipulation-Suite with "standard ADROIT benchmarks from RSS2018") — [RoboHive](https://github.com/vikashplus/robohive); original repo Apache-2.0 — [hand_dapg](https://github.com/aravindr93/hand_dapg).
- **RLBench**: task files include `screw_nail.py` and `hit_ball_with_queue.py` — [RLBench tasks](https://github.com/stepjam/RLBench/tree/master/rlbench/tasks).
- **ManiSkill3** table-top tasks: PegInsertionSide-v1, PlugCharger-v1, TurnFaucet-v1, AssemblingKits-v1, PullCubeTool-v1; "Hammering, Screws: None" — [ManiSkill3 tasks](https://maniskill.readthedocs.io/en/latest/tasks/table_top_gripper/index.html).
- **FurnitureBench** (real-world, Franka, "delta end-effector pose and gripper action commands at 10Hz", 5,100 demos / 219.6 h): 8 IKEA-inspired pieces + one-leg; screwing is required (lamp "inserts bulb but fails to screw"); FurnitureSim "built on IsaacGym and Factory" — [FurnitureBench](https://clvrai.github.io/furniture-bench/).
- **MimicGen / robosuite**: MimicGen tasks include "Hammer Cleanup", "Threading" (80%), "Nut Assembly" and "Nut-and-Bolt Assembly" (96%), the latter "from Isaac Gym Factory, as opposed to the other robosuite MuJoCo tasks"; real Stack/Coffee — [MimicGen](https://mimicgen.github.io/); robosuite (MuJoCo, control_freq=20) has NutAssembly, TwoArmPegInHole and TwoArmHandover ("A hammer is placed on a narrow table") — [robosuite envs](https://robosuite.ai/docs/modules/environments.html).
- **RoboTwin 2.0** (SAPIEN, 50 dual-arm tasks, 5 embodiments, 100k+ trajectories): includes "Beat Block Hammer"; real-world tests on COBOT-Magic were Stack Bowls, Handover Block, Pick Bottle, Click Bell (no hammer) — [RoboTwin 2.0](https://arxiv.org/html/2506.18088), [site](https://robotwin-platform.github.io/).
- **BEHAVIOR-1K** (1,000 activities, OmniGibson; real-apartment sim-to-real study) — [arXiv 2403.09227](https://arxiv.org/abs/2403.09227); knowledge base shows "assembling_furniture-0" (desk_top/bracket/leg with "attached" predicates); no hammer/screwdriver task found in the excerpt — [BEHAVIOR tasks](https://behavior.stanford.edu/knowledgebase/tasks/).
- **HumanoidToolBench**: G1 in MuJoCo; IceBreak uses a "Metal hammer" to break ice blocks; sim-only; MIT — [GitHub](https://github.com/SNU-PI/HumanoidToolBench).
- **Isaac Lab** ships Factory envs "Isaac-Factory-NutThread-Direct-v0: Thread the nut onto the first 2 threads of the bolt", PegInsert, GearMesh, plus FORGE force-sensing variants and AutoMate Assembly/Disassembly; "no dedicated tool-based environments (hammer, drill, screwdriver)" — [Isaac Lab environments](https://isaac-sim.github.io/IsaacLab/main/source/overview/environments.html).
- **Factory / IndustReal / AutoMate** (real-world counterparts for assembly, not tools): Factory = 60 part models, 3 envs, 7 controllers, RL nut-and-bolt, sim only — [arXiv 2205.03532](https://arxiv.org/abs/2205.03532); IndustReal transfers "contact-rich pick, place, and insertion tasks" to reality with SDF rewards and a policy-level action integrator — [arXiv 2305.17110](https://arxiv.org/abs/2305.17110); AutoMate: 100 plug/socket assemblies, specialists ≥80% on 80 assemblies, real "specialist mean success rate is 90.0%…generalist 86%", no threaded fasteners mentioned — [AutoMate site](https://bingjietang718.github.io/automate/), [arXiv 2407.08028](https://arxiv.org/abs/2407.08028).
- **NIST Assembly Task Boards** (physical, CAD/STL downloadable; ATB#1 purchasable from UMass Lowell): ATB#1 "peg insertions, gear meshing, electrical connector insertions, and nut threading"; ATB#2 belts, tensioners, "threading bolts"; no tool-driven screwing — [NIST](https://www.nist.gov/el/intelligent-systems-division-73500/robotic-grasping-and-manipulation-assembly/assembly).
- **TRI LBM Eval**: 49 Drake tasks, MIT/Apache; no tool tasks listed — [lbm_eval](https://github.com/ToyotaResearchInstitute/lbm_eval). **LIBERO**: 4 suites / 130 tasks; no tools identified — [LIBERO](https://lifelong-robot-learning.github.io/LIBERO/html/getting_started/overview.html). **DexMV**: pour, place-inside, relocate; no hammer — [DexMV](https://yzqin.github.io/dexmv/). **GenSim**: 100+ LLM-generated tasks, +25% real transfer, no impact tools — [arXiv 2310.01361](https://arxiv.org/abs/2310.01361). **TACO** is a 2.5K-sequence human bimanual hand-object dataset (RGB + 3D meshes, no tactile) — [arXiv 2401.08399](https://arxiv.org/abs/2401.08399). **ArtVIP**: articulated USD assets with "fine-tuned dynamic parameters", no tools — [arXiv 2506.04941](http://export.arxiv.org/api/query?search_query=ti:ArtVIP&max_results=3).

### Inferences
- Every hammer benchmark scores "success" by nail displacement or contact in a soft-contact simulator; none reports impact force, rebound, or grip slip, so they cannot validate C4/C5 behaviors.
- FurnitureBench + FurnitureSim (IsaacGym/Factory) is the only real-world benchmark with actual threaded screwing, but the screw is turned by rotating the gripper, i.e., one degree of separation and quasi-static.
- A new benchmark for power-tool screwing / nail driving with force-truth (nail depth, torque trace, cam-out events) would fill a gap that none of the surveyed suites covers.

### Gaps
- RLBench's simulator backend (CoppeliaSim/PyRep) and the physics of `screw_nail` were not verified in this session.
- BEHAVIOR-1K's full 1,000-task list was not enumerated; a hammer/drill activity beyond "assembling_furniture" cannot be excluded.
- HumanoidBench and RoboCasa task lists were not verified for hammer tasks.

## Key question 3 — Simulator fidelity for impacts, vibration, and screw threads; sim-to-real evidence for impact tasks

### Takeaway
All mainstream RL simulators model contact as soft/regularized constraints at 2–17 ms time steps (MuJoCo default 2 ms; Factory 1/60 s with 1 substep; Drake hydroelastic "does not introduce state"), so impulsive hammer strikes and drill vibration are at best qualitatively represented; real screw-thread geometry is simulated only by NVIDIA's Factory/IndustReal lineage (SDF contacts, ISO threads), and no simulator was found that models drill-bit engagement or cam-out.

### Cited Findings
- **MuJoCo**: contacts are soft constraints — "we drop the strict complementarity constraint at the heart of the LCP formulation", so "force and velocity in the contact normal direction can be simultaneously positive"; MuJoCo uses continuous-time soft dynamics rather than impulsive hard contacts to avoid Painlevé-type paradoxes — [MuJoCo computation](https://mujoco.readthedocs.io/en/stable/computation/index.html); no coefficient of restitution parameter; bouncing is obtained through solref's negative "direct" format, which allows "perfectly elastic collisions (damping = 0)", with the stability rule "timeconst parameter should be at least two times larger than the simulation time step" — [MuJoCo modeling](https://mujoco.readthedocs.io/en/stable/modeling.html); default `timestep` = 0.002 s, "the single most important parameter affecting the speed-accuracy trade-off" — [XMLreference source](https://raw.githubusercontent.com/google-deepmind/mujoco/main/doc/XMLreference.rst).
- **MJX**: MJX-JAX supports condim "1, 3, 4, 6", only CG/Newton solvers, convex meshes should have "200 vertices or less" (32 for convex-convex), can be "10x slower than MuJoCo" for a single scene and struggles with "Large, complex scenes with many contacts"; MJX-Warp supports all condim and all solvers except PGS/noslip but "Differentiability…is not currently available in MJX-Warp" — [MJX docs](https://mujoco.readthedocs.io/en/stable/mjx.html).
- **Newton** (v1.5.2 docs; Apache-2.0 code, CC-BY-4.0 docs; "initiated by Disney Research, Google DeepMind, and NVIDIA"; Linux Foundation project; "integrates MuJoCo Warp as its primary backend") — [Newton repo](https://github.com/newton-physics/newton), [docs](https://newton-physics.github.io/newton/stable/); default "hard SDF contacts - point contacts computed from SDF distance queries", opt-in hydroelastic "distributed contact areas", material `restitution` default 0.0 and "SolverXPBD requires enable_restitution=True"; SDFs recommended on every collidable mesh — [Newton collisions](https://newton-physics.github.io/newton/stable/concepts/collisions.html).
- **PhysX 5.6 (Isaac Sim/Lab)**: restitution defined as "the ratio of speeds after and before an impact"; TGS "will become the default solver" with substeps equal to position iterations; `setMaxDepenetrationVelocity()` for unstable contacts; speculative CCD flag for fast bodies; contact/rest offsets — [PhysX RigidBodyDynamics](https://nvidia-omniverse.github.io/PhysX/physx/5.6.0/docs/RigidBodyDynamics.html), [RigidBodyCollision](https://nvidia-omniverse.github.io/PhysX/physx/5.6.0/docs/RigidBodyCollision.html).
- **Drake hydroelastic**: rigid bodies "allowed to penetrate slightly, as if the rigid body had a slightly deformable layer"; "Hydroelastics cannot model true deformations given the model does not introduce state. Therefore effects such as tangential compliance or short time scale waves are not captured"; "values as high or larger than 10⁸ Pa are seldom used"; no rigid-rigid contact surfaces — [Drake hydroelastic guide](https://drake.mit.edu/doxygen_cxx/group__hydroelastic__user__guide.html).
- **Genesis**: unified Rigid/FEM/MPM/PBD/SPH/uipc solvers with SAP coupling, autodiff, Apache 2.0; no stated impact-fidelity claims — [Genesis repo](https://github.com/Genesis-Embodied-AI/Genesis).
- **Screw threads**: Factory computes "one contact per triangle-mesh face" from SDFs stored as GPU 3D textures, reduces ~16k contacts to ~300 by clustering; "For Δt=1/60 s, we require only 1 substep and 16 iterations for stable simulation"; nuts/bolts "conform to ISO 724, ISO 965, and ISO 286 standards" with "finite clearances between their threads, thus experiencing 6-DOF kinematics"; "1000 simultaneous nut-and-bolt assemblies in real-time on a single GPU"; no real-robot experiments — [Factory (ar5iv)](https://ar5iv.labs.arxiv.org/html/2205.03532). Isaac Lab's NutThread task threads only "the first 2 threads of the bolt" — [Isaac Lab envs](https://isaac-sim.github.io/IsaacLab/main/source/overview/environments.html).
- **Sim-to-real for impulsive/dynamic tasks**: TossingBot learns "residuals on top of control parameters predicted by a physics simulator" in the real world, "85% throwing accuracy" at 600+ grasps/h — [arXiv 1903.11239](https://arxiv.org/abs/1903.11239); SimToolReal transfers hammer *trajectories* zero-shot but warns it "does not guarantee functional task completion, especially for high-force interactions" — [SimToolReal](https://arxiv.org/html/2602.16863); DexScrew reports direct sim-to-real screwdriving progress of only 41.6% vs 95% after real tactile BC, with sim run at 200 Hz — [DexScrew](https://arxiv.org/html/2512.02011); I.AM. (impact-aware, torque-controlled tossing) lists Algoryx Simulation as a partner — [CORDIS](https://cordis.europa.eu/project/id/871899).
- **Tactile simulation**: TacSL renders visuotactile images and force fields "over 200× faster than the prior state-of-the-art" in Isaac Gym with sim-to-real transfer — [TacSL](https://iakinola23.github.io/tacsl/); Isaac Lab's Visuo-Tactile Sensor "provides realistic tactile feedback through integration with TacSL", demo on the discontinued GelSight R1.5, force fields need "Signed Distance Field (SDF) queries" — [Isaac Lab tactile sensor](https://isaac-sim.github.io/IsaacLab/main/source/overview/core-concepts/sensors/visuo_tactile_sensor.html); TacEx simulates GelSight Mini in Isaac Sim via Taxim, UIPC FEM, FOTS and PhysX soft bodies — [TacEx](https://sites.google.com/view/tacex); other tactile sims named in the literature: SimTac, Taccel, UniVTAC, ETac — [awesome-touch](https://github.com/sun254667/awesome-touch).

### Inferences
- (a) Impulsive impacts through a held tool: MuJoCo/PhysX/Newton resolve a hammer strike as a few-millisecond soft penetration with solver-dependent rebound; nothing found benchmarks impact force magnitude or grip-slip during a strike, so these sims are usable for kinematic/coarse-force behavior only. Drake's hydroelastic model is explicitly stateless and misses "short time scale waves".
- (b) Drill/driver vibration: no simulator in this survey models tool vibration; at 2–17 ms steps a 20–200 Hz vibration is at or below the Nyquist limit of the physics step, so vibration signatures a tactile policy would rely on cannot be synthesized faithfully (inference from the time-step facts above).
- (c) Screw threads/engagement: Factory-lineage SDF contact is the only thread-level model, is quasi-static (1/60 s, 1 substep), and has never been validated on a real robot in the original paper; no simulator models bit-recess engagement or cam-out, so engagement detection must be learned from real data.
- Practical implication: a hybrid plan (sim for kinematics/regrasp/alignment; real-world RL/BC with tactile+torque for strike/drive phases, as in TossingBot and DexScrew) is the only sim-to-real pattern with evidence behind it.

### Gaps
- No documentation was retrieved on Algoryx AGX or Vortex screw/thread models, nor any simulator explicitly claiming cam-out modeling (search budget exhausted); absence is by survey, not proof.
- No quantitative study comparing simulated vs measured hammer-impact forces was found.
- PhysX substep guidance for high-speed impacts and Isaac Sim's default physics dt were not retrieved.

## Key question 4 — Open-source stacks as starting points (license, tactile/force inputs, control rate)

### Takeaway
No open VLA stack (LeRobot, openpi, OpenVLA-OFT, GR00T) documents a force/torque or tactile observation stream; the only open code that already implements a slow-fast tactile loop is Reactive Diffusion Policy (MIT), while TacSL/Isaac Lab (BSD-3) and TacEx cover tactile simulation, Sparsh (CC BY-NC) covers tactile encoders, and HIL-SERL (Apache-2.0) covers real-world RL with impedance control.

### Cited Findings
- **LeRobot**: Apache 2.0; policies ACT, Diffusion, VQ-BeT, Multitask DiT, Pi0, Pi0Fast, Pi0.5, GR00T N1.7, SmolVLA, XVLA, EO-1, MolmoAct2, WALL-OSS, EVO1; RL: HIL-SERL, TDMPC; no force/tactile stream documented — [LeRobot](https://github.com/huggingface/lerobot).
- **OpenVLA-OFT**: MIT; inputs "full_image", "wrist_image", "robot proprioceptive state"; ALOHA and LIBERO; no force/tactile — [openvla-oft](https://github.com/moojink/openvla-oft).
- **openpi**: Apache-2.0; π0, π0-FAST, π0.5; image + language inputs, fine-tuning supported; no force/tactile documented — [openpi](https://github.com/Physical-Intelligence/openpi).
- **Isaac-GR00T**: code Apache 2.0, "Model weights: NVIDIA Open Model License"; N1.7 GA (N1.6/N1.5 on branches); action horizon expanded 16 -> 40; language + images + proprioceptive state, no force/tactile — [Isaac-GR00T](https://github.com/NVIDIA/Isaac-GR00T).
- **Reactive Diffusion Policy code**: MIT (primary license, with third-party notices) — [LICENSE](https://raw.githubusercontent.com/xiaoxiaoxh/reactive_diffusion_policy/main/LICENSE); supports "1-2 GelSight Mini tactile sensors", MCTac, "(optional) joint torque sensors", 24 fps recording, RDP trained at 24 fps vs DP 12 fps, Flexiv Rizon 4 default and Franka Research 3, TactAR on Meta Quest 3 — [RDP repo](https://github.com/xiaoxiaoxh/reactive_diffusion_policy).
- **Sparsh**: Creative Commons Attribution-NonCommercial 4.0 — [LICENSE.md](https://raw.githubusercontent.com/facebookresearch/sparsh/main/LICENSE.md); DIGIT, GelSight'17, GelSight Mini; MAE/DINO/JEPA variants; force estimation, slip, pose — [sparsh](https://github.com/facebookresearch/sparsh); the main repo is marked archived (metadata via GitHub API) and a successor "sparsh-multisensory-touch" adds Sparsh-Skin (magnetic) and Sparsh-X (tactile image + audio + IMU + pressure, Digit 360) — [sparsh-multisensory-touch](https://github.com/facebookresearch/sparsh-multisensory-touch).
- **TacSL**: Isaac Gym branch of IsaacGymEnvs under BSD 3-Clause — [LICENSE](https://raw.githubusercontent.com/isaac-sim/IsaacGymEnvs/tacsl/LICENSE.txt); integrated into Isaac Lab (BSD-3; isaaclab_mimic Apache 2.0; Isaac Sim 6.1 / PhysX) as the Visuo-Tactile Sensor — [Isaac Lab repo](https://github.com/isaac-sim/IsaacLab), [sensor docs](https://isaac-sim.github.io/IsaacLab/main/source/overview/core-concepts/sensors/visuo_tactile_sensor.html). **TacEx**: Isaac Sim/Lab GelSight Mini simulation (Taxim, UIPC, FOTS); license not stated on the page — [TacEx](https://sites.google.com/view/tacex).
- **HIL-SERL**: Apache-2.0; "impedance-based serl_franka_controllers", wrist cameras; tasks RAM insertion, USB pickup/insertion, handover, egg flip; "near-perfect success rates" — [hil-serl](https://github.com/rail-berkeley/hil-serl).
- **MuJoCo MPC**: Apache-2.0; iLQG, Gradient Descent, Predictive Sampling; "real-time predictive control with MuJoCo"; bimanual and in-hand demos — [mujoco_mpc](https://github.com/google-deepmind/mujoco_mpc).
- **Newton / Genesis**: Apache-2.0 each (see KQ3 sources).
- Small community stacks already pairing tactile arrays with open VLAs exist (e.g., π0.5 fine-tuned with a fingertip tactile array in Genesis; SO-101 + LeRobot ACT/SmolVLA with tactile) — [open-drawer](https://github.com/Akbro23/open-drawer), [TactileVLA-Edge](https://github.com/vishal-naveen/TactileVLA-Edge).

### Inferences
- A viable open starting point is: openpi/LeRobot π0.5-class slow policy (Apache) + RDP-style fast tactile tokenizer (MIT) + HIL-SERL-style impedance control and real-world RL (Apache) + Isaac Lab/TacSL (BSD-3) for pre-training regrasp/alignment; Sparsh encoders would need a non-commercial exception or replacement (CC BY-NC).
- Joint-torque streams must be added by the integrator; none of the VLA stacks expose an effort/torque observation key.

### Gaps
- Exact inference rates for openpi/OpenVLA-OFT/LeRobot policies and any native F/T dataset keys were not found in the fetched README content.
- TacEx's license and the state of Isaac Lab's tactile sensor for non-R1.5 sensors were not verified.
